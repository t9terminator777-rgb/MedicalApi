# MedicalApi — учебный Web API клиники на C#

Учебный ASP.NET Core Web API для управления пациентами, медицинскими справками, каталогом видов справок и записями на приём. Swagger UI используется для просмотра и ручной проверки запросов.

## Запуск

Требуется .NET 10 SDK.

```powershell
dotnet restore
dotnet run --urls http://localhost:5138
```

Откройте Swagger: <http://localhost:5138/swagger>.

## Возможности

- Пациенты: список, поиск по Id, создание, изменение, удаление.
- Справки: список, получение по Id, создание, изменение, удаление.
- Каталог видов справок: CRUD; изначально есть четыре вида с ценой и сроком действия.
- При создании справки сервер проверяет пациента и вид справки, а название и цену берёт из каталога.
- Справки можно фильтровать по пациенту или названию, а также сортировать по Id, цене и дате.
- Для карточки пациента есть адрес `/api/patients/{id}/spravki`.
- Дополнительный модуль записей к врачу: список, получение, создание, изменение, удаление.
- Проверяются обязательные поля, даты, цена, существование связанных пациента и вида справки.
- Удаление пациента удаляет также его справки и записи на приём; вид справки, уже использованный в справке, удалить нельзя.

## Примеры запросов

Создать пациента через `POST /api/patients`:

```json
{
  "name": "Алиса",
  "birthDate": "2000-05-15",
  "phone": "+996111222333",
  "email": "alice@example.com",
  "bloodType": "O+"
}
```

Создать справку через `POST /api/spravki` (название и стоимость не присылаются, они берутся из каталога):

```json
{
  "patientId": 1,
  "spravkaTypeId": 2
}
```

Отфильтровать и отсортировать справки:

```text
GET /api/spravki?patientId=1&sortBy=price&order=desc
GET /api/spravki?search=бассейн
```

Коды ответов: `200 OK` — успешное чтение/изменение, `201 Created` — создана запись, `204 No Content` — удалена запись, `400 Bad Request` — неверные данные или связь, `404 Not Found` — запись не найдена, `409 Conflict` — нельзя удалить используемый вид справки.

## Поиск и регистрация по ПИН

Для регистрации пациента нужен PostgreSQL и .NET 10. Укажи строку подключения к учебной БД в переменной окружения, затем примени миграцию из папки проекта.

```powershell
$env:ConnectionStrings__MedicalDb = 'Host=localhost;Database=medical_api;Username=postgres;Password=ТВОЙ_ПАРОЛЬ'
dotnet run --no-launch-profile -- --migrate
dotnet run --launch-profile http
```

Swagger в Development открывается по адресу `http://localhost:5046/swagger`. Запуск Production: `dotnet run --no-launch-profile`. Справки и записи на приём продолжают храниться в памяти. Пациенты хранятся в PostgreSQL.

| Запрос | Результат |
| --- | --- |
| `GET /api/GosReestr/21203199850123` | 200, ФИО и дата рождения |
| `GET /api/GosReestr/abc` | 400, ошибка формата |
| `GET /api/GosReestr/11111111111111` | 404, ПИН не найден |
| `GET /api/GosReestr/20101200000000` | 503, тестовый сбой госреестра |
| `POST /api/Patients` с телом `{"pin":"21203199850123"}` | 201 после применения миграции, ФИО и дата рождения берутся из госреестра |
| Повторная регистрация того же ПИН | 409, включая одновременные запросы благодаря уникальному индексу |
| Регистрация по неизвестному ПИН | 400 |
| Регистрация при сбое госреестра | 503, пациент не сохраняется |

### Ошибка в Development и Production

До обработки исключения обычный ответ на сбой содержал бы статус 500. В Development страница ошибки показывает исключение, имена методов, пути к исходникам и номера строк. Эти сведения раскрывают устройство приложения. В Production подробности необработанной ошибки записываются в журнал сервера, а клиент получает 500 без стека. В итоговом варианте сбой госреестра обрабатывается явно и возвращает 503 в обоих режимах.
